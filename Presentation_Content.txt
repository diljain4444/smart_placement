SLIDE 2: PROBLEM STATEMENT
================================================================================

Problems Faced by Engineering Students During Placement Season:
--------------------------------------------------------------
1. No access to realistic mock interview practice with instant feedback
2. Resumes are not ATS (Applicant Tracking System) optimized, leading to rejections
3. Students don't know how to tailor resumes for specific job descriptions
4. No personalized roadmap — students don't know what to study, in what order
5. Scattered learning resources across the internet with no curation
6. No way to quickly ask questions about study material / syllabus documents

Our Solution:
-------------
Smart Placement is an all-in-one AI-powered platform that addresses every
challenge a student faces during placement preparation — from practicing
interviews with a talking AI avatar, to building ATS-friendly resumes,
to getting a personalized study roadmap.

SLIDE 6: MODULE 1 — AI MOCK INTERVIEW (Detailed Working)
================================================================================

PURPOSE:
--------
An adaptive, human-in-the-loop AI mock interviewer that simulates a real
technical interview experience using a video avatar, voice interaction,
and intelligent question progression.

HOW IT WORKS (Step by Step):
----------------------------

Step 1: Resume Upload & Processing
   → User uploads resume (PDF/DOCX) + optional Job Description
   → Backend calls preprocess() to extract text using PyMuPDF/docx2txt
   → Text is cleaned (regex removes page markers, non-ASCII, redundant spaces)
   → LLM chain extracts structured info: Education, Skills, Projects
   → If JD provided, it's cleaned and stored as jd_context

Step 2: Interview Session Initialization
   → Backend creates a unique UUID session ID and thread ID
   → LangGraph workflow is initialized with candidate profile data
   → First question is generated using the LLM
   → Edge-TTS converts the question text to speech (MP3 audio)
   → Audio is base64-encoded and sent to frontend

Step 3: Interactive Q&A Loop (The Core)
   → AI avatar (video) plays the question with synchronized audio
   → Candidate answers via:
     - Voice Mode: Browser microphone → MediaRecorder API → audio blob
       → sent to backend → Groq Whisper transcribes to text
     - Text Mode: User types answer in textarea → sent as text
   → LLM evaluates the answer:
     - Scores it 0-10
     - Determines if follow-up is needed
     - Generates concise feedback (1-2 sentences)
   → If follow-up needed AND depth < 2: asks a deeper follow-up question
   → If not: moves to a new topic
   → Both feedback and next question are converted to TTS audio
   → Avatar plays feedback audio first, then question audio sequentially

Step 4: Interview Completion & Report
   → After covering ≥ 5 topics (or user clicks "End Interview" after ≥ 3)
   → LLM analyzes full conversation history
   → Generates comprehensive review containing:
     - Overall Rating (out of 10)
     - Communication Score
     - Confidence Score
     - Per-Topic Ratings with weaknesses identified
     - Overall Strengths list
     - Overall Weaknesses list
     - Top Recommendations
     - Personalized Learning Roadmap (topics, concepts, resources, durations)

INTERVIEW FLOW MODES:
---------------------
• "Resume Only" mode: Questions based purely on candidate's resume
• "Resume + JD" mode: Questions progress through structured stages:
   1. Personal Introduction
   2. JD-Required Skills Assessment
   3. Project Deep-Dive
   4. Role Alignment Evaluation
   5. Gap Assessment
   6. Behavioral Scenarios

LANGGRAPH STATE MACHINE:
-------------------------
  START → question_generator (interrupts for user answer)
              ↓
        answer_evaluator
              ↓
        route_after_eval
           /        \
      (continue)   (end: topics ≥ 5 or user forced end)
          ↓             ↓
  question_generator   report_ready → END

KEY DATA MODELS:
----------------
• state (TypedDict): Tracks education, skills, projects, interview_mode,
  jd_context, user_question, user_answer, history, current_depth,
  feedback, covered_topics, follow_up_required, current_topic, score, review_final

• user_info (Pydantic): education, skills[], projects[]

• ans_eval (Pydantic): score (0-10), follow_up_required (bool), feedback (str)

• review (Pydantic): overall_rating, topic[] (with ratings & weaknesses),
  overall_strength[], overall_weakness[], top_recommendation[],
  road_map[] (topic, concepts, duration, resources),
  communication_score, confidence_score

AVATAR PANEL (Frontend):
-------------------------
• 3 pre-rendered MP4 video states:
  - new_final_question.mp4 → Green glow, speaking equalizer bars
  - new_waiting.mp4        → Slate glow, idle state
  - new_hearing.mp4        → Blue glow, microphone wave bars
• Videos crossfade using CSS opacity transitions
• Audio played via HTMLAudioElement with base64 data URLs
• Browser autoplay unlocked using silent WAV trick during user gesture
• Sequential playback: feedback audio → question audio → return to waiting

SLIDE 7: MODULE 2 — RESUME SUITE (Builder + Modifier + Rater)
================================================================================

PURPOSE:
--------
A comprehensive AI-powered resume engineering workstation that builds,
rewrites, scores, and exports professional resumes as pixel-perfect PDFs.

SUB-MODULE 2A: RESUME BUILDER
------------------------------
How It Works:
1. User fills a 7-section form:
   - Personal Information (Name, Email, Phone, Location, LinkedIn, GitHub, Portfolio)
   - Professional Summary
   - Skills (comma-separated)
   - Education (repeatable: degree, institution, years, GPA)
   - Work Experience (repeatable: role, company, dates, responsibilities)
   - Projects (repeatable: title, tech stack, description, link)
   - Certifications (repeatable: name, issuer, date)
   - Achievements

2. Frontend validates all fields:
   - Email format (email-validator library)
   - Phone: 10-15 digits after stripping non-digits
   - URLs: regex pattern validation
   - Years: 4-digit or "Present"
   - Required fields: name (min 2 chars), skills, at least 1 project or experience

3. Data sent as JSON to backend → LLM generates a professional Resume object
   → LLM uses structured output (Pydantic schema) to ensure valid format

4. If LLM output fails validation: Self-healing parser feeds the error back
   to the LLM with a FIX_PROMPT → LLM corrects its own JSON (max 1 retry)

5. Resume Pydantic model → rendered to PDF using ReportLab Platypus:
   - SimpleDocTemplate with custom page margins
   - ParagraphStyle for each section (headings, body, bullets)
   - HRFlowable for horizontal dividers
   - ListFlowable for bullet points
   - All non-ASCII characters sanitized (en-dashes, curly quotes → ASCII)

6. PDF streamed back to frontend → auto-downloaded as "{Name}_Resume.pdf"

SUB-MODULE 2B: RESUME MODIFIER
-------------------------------
How It Works:
1. User provides resume data via:
   - Option A: Upload existing resume (PDF/DOCX/TXT) → text extracted
   - Option B: Fill the same 7-section form manually

2. User enters the target Job Description (min 50 characters)

3. User adjusts "Creativity" temperature slider (0.2 = conservative, 0.9 = creative)

4. Backend tailors the resume:
   - Rewrites bullet points to match JD keywords
   - Reorders skills to prioritize JD-relevant ones
   - Adjusts professional summary for the target role
   - Does NOT fabricate information — only restructures and rephrases

5. Modified resume → PDF generated → auto-downloaded as "Modified_Resume.pdf"

SUB-MODULE 2C: RESUME RATER (Hybrid Scoring)
----------------------------------------------
How It Works:
1. User provides resume text (paste or upload) + target Job Description

2. STATISTICAL ANALYSIS (35% weight):
   - Tokenization: Extract words using regex [A-Za-z][A-Za-z0-9+.#-]{1,}
   - Remove stopwords (common English words)
   - Compute Term Frequency vectors for both resume and JD
   - Calculate Cosine Similarity:
     cos(θ) = (A · B) / (||A|| × ||B||)
   - Extract top 25 JD keywords
   - Identify matched keywords and missing keywords

3. LLM QUALITATIVE ANALYSIS (65% weight):
   - AI acts as a senior recruiter reviewing the resume against the JD
   - Scores on 5 metrics (each 0-100):
     a) Content Quality Score
     b) Keyword Alignment Score
     c) ATS Friendliness Score
     d) Formatting Score
     e) Overall Score
   - Provides: Strengths, Weaknesses, Missing Keywords, Suggestions, Summary

4. HYBRID SCORE CALCULATION:
   Hybrid Score = round(0.35 × Similarity Score + 0.65 × LLM Overall Score)

5. Frontend displays:
   - Large overall hybrid score badge (out of 100)
   - 5-metric score cards
   - Recruiter summary text
   - Strengths & Weaknesses bullet points
   - Green tags for matched keywords, Red tags for missing keywords

KEY DATA MODELS:
----------------
• Resume (Pydantic): Full resume structure with validators for phone,
  email, URLs, skill deduplication, and experience/project requirements

• KeywordMatch: similarity_score, matched_keywords[], missing_keywords[]

• ResumeRating: overall_score, content_quality_score, keyword_alignment_score,
  ats_friendliness_score, formatting_score, strengths[], weaknesses[],
  missing_keywords[], suggestions[], summary_feedback

• HybridRating: hybrid_score, similarity (KeywordMatch), llm_rating (ResumeRating)

SLIDE 9: MODULE 4 — DOCUMENT Q&A (RAG Engine)
================================================================================

PURPOSE:
--------
An advanced Retrieval-Augmented Generation (RAG) system that lets users
upload any document and ask questions, receiving precise, fact-grounded
answers with zero hallucination.

HOW IT WORKS (Detailed Pipeline):
-----------------------------------

Phase 1: Document Upload & Processing
   1. User uploads document (PDF, DOCX, CSV, TXT, or images)
   2. Backend ingests file using appropriate loader:
      - PDF → PyMuPDFLoader
      - DOCX → Docx2txtLoader
      - CSV → CSVLoader
      - TXT → TextLoader
      - Images → UnstructuredImageLoader (with OCR)
   3. Text is cleaned (remove page markers, non-ASCII, excessive whitespace)
   4. Text is split into chunks:
      → RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=100)
   5. Two indexes are created:
      a) FAISS Vector Index: Chunks embedded using HuggingFace BAAI/bge-small-en-v1.5
      b) BM25 Sparse Index: Keyword-based retrieval using rank-bm25
   6. Session ID returned to frontend with filename and chunk count

Phase 2: Question Answering (LangGraph Pipeline)
   For each user question, the following 5-stage pipeline executes:

   Stage 1: Multi-Query Expansion
      → User's question is expanded into 3 semantic query variants by LLM
      → Purpose: Capture different phrasings to improve retrieval recall
      → Example: "What is the salary?" → ["compensation details",
        "pay range mentioned", "salary information provided"]

   Stage 2: Hybrid Search (for each of the 3 queries)
      → Dense Search: FAISS retrieves top-5 semantically similar chunks
      → Sparse Search: BM25 retrieves top-5 keyword-matching chunks
      → Total: Up to 30 candidate chunks (3 queries × 2 methods × 5 each)

   Stage 3: Merging & Deduplication
      → Duplicate chunks identified by text hash
      → For each unique chunk, track:
        - Frequency (how many queries found it)
        - Source retrievers (vector, bm25, or both)
        - Which query variants found it

   Stage 4: Re-Ranking (Fusion Score)
      → Score = (Frequency × 2) + (3 if found by BOTH vector AND bm25, else 1)
                + (Count of unique queries that found it)
      → Chunks sorted by score in descending order
      → Top 5 chunks selected as final context

   Stage 5: Answer Generation
      → Top 5 chunks formatted as numbered sources [Source 1], [Source 2], etc.
      → LLM (temperature=0.1 for factual accuracy) generates answer
      → Strict instruction: "ONLY use facts explicitly stated in context.
        If not present, respond: 'This information is not available in the
        uploaded document.'"

LANGGRAPH RAG WORKFLOW:
-----------------------
  START → multi_query_retrieval → merging → re_ranking → context_builder
                                                              ↓
                                                       answer_generator → END

LLM CONFIGURATION:
-------------------
• Query Expansion: ChatGroq (temperature=0.4) — slightly creative for variety
• Answer Generation: ChatGroq (temperature=0.1) — highly deterministic for accuracy
• Embedding Model: HuggingFace BAAI/bge-small-en-v1.5 (runs locally, no API cost)

FRONTEND (DocQA.jsx):
---------------------
• Phase 1 UI: Drag-and-drop file upload zone with format hints
• Phase 2 UI: Chat interface
  - User messages: Indigo background, right-aligned
  - AI messages: Dark background, left-aligned
  - Thinking indicator: Three pulsing dots with "Analyzing document..."
  - Bottom input bar with "Ask" button
  - Header shows filename and chunk count badge

SLIDE 10: MODULE 5 — PLACEMENT ROADMAP GENERATOR
================================================================================

PURPOSE:
--------
An AI-powered career roadmap generator tailored for Indian engineering students.
It evaluates the student's current preparation level, identifies gaps, and
produces a structured, deadline-aware preparation plan.

HOW IT WORKS:
--------------

Step 1: Student Profile Collection (17 Fields)
   Academic Information:
     - Year (1st to 4th year)
     - Branch
     - DSA Problems Solved (<50, 50-150, 150-300, 300+)
     - Known Skills (select from 18 options + custom input)
     - Project Count
     - Certifications

   CS Fundamentals Confidence (4 subjects):
     - Operating Systems: not started / familiar / strong
     - DBMS: not started / familiar / strong
     - Computer Networks: not started / familiar / strong
     - OOP: not started / familiar / strong

   Target Goals:
     - Target Role: SDE, AI/ML Engineer, Data Analyst, Data Scientist
     - Company Tier: Service-based, Product-based mid-tier, FAANG/top product, Startups
     - Placement Mode: On-campus / Off-campus
     - Dream Companies

   Constraints:
     - Available Hours per Week (1-80)
     - Learning Style: Videos, Docs, Practice-first, Mixed
     - Deadline (optional date)

Step 2: Gap Analysis (LangGraph Node 1)
   → LLM evaluates current skills vs target role and company tier
   → Outputs a concise 2-3 sentence gap assessment
   → Example: "Strong DSA base but needs system design depth for FAANG-level
     product companies. Missing cloud deployment and CI/CD skills."

Step 3: Phase Generation (LangGraph Node 2)
   → LLM generates 3 to 6 ordered preparation phases
   → Each phase contains:
     - Phase Name (e.g., "DSA Mastery", "System Design Foundations")
     - Duration in Weeks
     - Priority: High / Medium / Low
     - Topics to Cover
     - Milestone (measurable goal)
     - Suggested Project (optional)
     - Why This Order (pedagogical justification)

Step 4: Deadline Adjustment (LangGraph Node 3)
   → Calculates weeks until student's deadline
   → If total phase duration exceeds available weeks:
     a) First try: LLM is asked to compress and merge phases
     b) If LLM fails: Force-Fit Algorithm activates:
        - Assigns priority weights: High=1.0, Medium=0.7, Low=0.4
        - Calculates weighted durations proportionally
        - Distributes available weeks proportionally to priority
        - Ensures every phase gets at least 1 week
        - Final phase absorbs remaining rounding margin

Step 5: Finalization (LangGraph Node 4)
   → Compiles final output: gap summary, phases, weekly time commitment

LANGGRAPH PIPELINE:
-------------------
  START → analyze_gap → generate_phases → adjust_for_deadline → finalize → END

FRONTEND (Roadmap.jsx):
------------------------
• Form View: 3 sections of inputs (Where You Are, Where You Want to Go, Constraints)
• Skills Selection: 18 pre-defined pill buttons + custom skill text input
• Results View:
  - Gap Analysis Summary card
  - Meta badges: Weekly commitment, total weeks, number of phases
  - Phase Timeline: Sequential cards with priority badges (🔴 High, 🟡 Medium, 🟢 Low),
    topic pills, milestone, suggested project box, and "Why This Order" explanation

SLIDE 12: KEY ALGORITHMS & AI TECHNIQUES
================================================================================

1. LangGraph State Machines (Used in 3 modules)
   ─────────────────────────────────────────────
   - Interview: Human-in-the-loop with interrupt() mechanism for user input
   - RAG: 5-stage pipeline (query expansion → hybrid search → rerank → answer)
   - Roadmap: 4-stage pipeline (gap analysis → phase generation → deadline fit → finalize)
   - MemorySaver checkpointer preserves conversation state across requests

2. Human-in-the-Loop Pattern (Interview)
   ─────────────────────────────────────────
   - LangGraph's interrupt() pauses execution until user answers
   - Command(resume=answer) resumes the graph with user's response
   - Enables true conversational flow with server-side state persistence

3. Hybrid Retrieval (RAG)
   ─────────────────────────
   - Dense: FAISS vector similarity using HuggingFace embeddings
   - Sparse: BM25 keyword matching using term frequency
   - Fusion: Reciprocal Rank scoring combining both approaches
   - Multi-Query: 3 semantic variants per question for better recall

4. Cosine Similarity (Resume Rater)
   ─────────────────────────────────
   - Pure-Python TF vector computation
   - cos(θ) = (A · B) / (||A|| × ||B||)
   - Applied to resume vs JD term-frequency vectors

5. Hybrid Scoring Formula (Resume Rater)
   ─────────────────────────────────────────
   Hybrid Score = round(0.35 × Cosine Similarity + 0.65 × LLM Score)
   - Combines deterministic metrics with qualitative AI evaluation

6. Self-Healing JSON Parser (Resume Backend)
   ──────────────────────────────────────────
   - If LLM output fails Pydantic validation
   - Error + raw output fed back to LLM via FIX_PROMPT
   - LLM corrects its own JSON (1 retry max)

7. Priority-Weighted Force-Fit (Roadmap)
   ──────────────────────────────────────
   - When phases exceed deadline, proportional compression:
     High=1.0, Medium=0.7, Low=0.4 weights
   - Ensures every phase gets ≥ 1 week
   - Final phase absorbs rounding margin

8. Neural Text-to-Speech (Interview)
   ──────────────────────────────────
   - Edge-TTS with Microsoft's en-US-GuyNeural voice
   - Rate adjusted to -10% for natural pacing
   - Audio converted to base64 for inline browser playback

9. Speech-to-Text Transcription (Interview)
   ────────────────────────────────────────
   - Groq Whisper (whisper-large-v3-turbo model)
   - Raw audio saved to temp .wav → transcribed via API
   - Transcript used as interview answer

AUDIO SEQUENCING LOGIC:
-------------------------
1. New question arrives → audioSeqId incremented
2. stopAudio() called to halt any previous playback
3. Avatar transitions to "new_final_question" state
4. playClip(feedbackAudio) → awaits completion
5. playClip(questionAudio) → awaits completion
6. Avatar returns to "new_waiting" state
7. If browser blocks autoplay → "Start Interview" button appears
8. "Replay Question Audio" button available for re-listening

------------------------------
• A 44-byte silent WAV audio is played inside the "Start Interview"
  button's click handler (user gesture context)

SLIDE 16: VALIDATION & ERROR HANDLING
================================================================================

FRONTEND VALIDATION (ResumeForm.jsx):
--------------------------------------
• Name: Required, minimum 2 characters
• Email: Regex pattern validation
• Phone: Strip non-digits, require 10-15 digit count
• URLs (LinkedIn, GitHub, Portfolio): Regex pattern validation
• Years: Must be 4-digit year or "Present"
• Skills: At least one non-empty skill required
• Projects/Experience: At least one entry required

BACKEND VALIDATION (resume_validators.py):
-------------------------------------------
8 validation functions, each returning (is_valid: bool, error_message: str):
1. required(value, field_name) — Fails if None or whitespace
2. min_length(value, n, field_name) — Checks minimum character length
3. validate_name(value) — Requires ≥ 2 characters
4. validate_email_format(value) — Uses email_validator library
5. validate_phone(value) — 10-15 digits after stripping non-digits
6. validate_url(value, field_name) — Regex URL pattern
7. validate_year(value) — 4-digit year or "present"
8. validate_comma_list(value) — At least one non-empty element

PYDANTIC MODEL VALIDATION (resume_backend.py):
-----------------------------------------------
• Resume model validates: phone format, URL normalization, skill deduplication
• Self-healing parser: If LLM JSON fails validation, feeds error back to LLM
• Maximum 1 retry for automatic correction

ERROR HANDLING PATTERNS:
-------------------------
• All API endpoints wrapped in try/except → return proper HTTP error codes
• Frontend displays error banners with descriptive messages
• Graceful degradation: If TTS fails, text-only mode continues
• Audio autoplay blocked: Manual "Start" button appears as fallback
